🔴 Tightly Coupled Engines (Synchronous RPC / Hard ACID)
Why Coupled? When a customer checkout is initiated, the platform cannot proceed without an authoritative dynamic price, confirmed inventory reservation, and payment lock. These services communicate via sub-50ms gRPC within a strict two-phase commit or fast rollback loop.
● Order Orchestrator ↔ Dynamic Rate Card ● Checkout Gateway ↔ Inventory Lock ● Auth Token Validator (In-Memory mTLS)
🟢 Loosely Decoupled Engines (Asynchronous Kafka / Eventual Consistency)
Why Decoupled? High-frequency telemetry (20k pings/sec), route matching math, push notifications, demand ML forecasting, and financial journal entries are decoupled via Kafka Event Streaming & Transactional Outbox. If notification or billing is slow, checkout is never blocked.
● Courier Telemetry → ScyllaDB ● Order Completed → Double-Entry Ledger ● Demand AI Worker → Redis Surge Cache

⚖️ Engineering Trade-off Matrix: Coupled (Sync) vs Decoupled (Async)
Architectural Decision Record (ADR-04)
Architectural Dimension Tightly Coupled (Synchronous gRPC) Loosely Decoupled (Asynchronous Kafka / Outbox) DeliverQ Implementation Decision
Primary Interaction Order Checkout ↔ Dynamic Rate Card ↔ Stock Lock Telemetry → Matcher → Ledger → Push Notifications Hybrid architecture: Sync for authorative money & stock, Async for everything else.
Latency Requirement Hard SLA < 50ms (User waiting on mobile screen) Eventual consistency: 200ms – 3000ms SLA gRPC with HTTP/2 multiplexing for internal sync; Kafka consumer groups for async.
Failure Blast Radius High: If callee crashes, caller fails or triggers fallback Zero: Messages persist safely in Kafka broker partitions Resilience4j circuit breaker on Rate Card; Fallback to static base rate if ML surge times out.
Consistency Model Strict Linearizable ACID / Distributed Redlock Eventual Consistency (BASE) via Transactional Outbox Debezium CDC tails PostgreSQL WAL logs, guaranteeing At-Least-Once delivery to Kafka.
Throughput & Scaling Tied to thread pool & database connection pool limits Massive: 100,000+ msg/sec buffered without backpressure Telemetry ingestion decoupled on ScyllaDB + Redis GEO; Order DB untouched by GPS pings.

⏱ End-to-End Distributed Order Lifecycle Sequence
T+0ms to T+28m Transaction Flow
T + 0 ms
1. Multi-Basket Order Ingestion & Gateway Ingress Envoy WAF → gRPC
Consumer submits checkout cart containing food and pharmacy items. Kong API Gateway verifies JWT bearer token, validates rate limits, and routes payload to the Order Orchestrator Saga.
T + 120 ms
2. Synchronous Rate Card & Multi-Vertical Pricing gRPC Protobuf (P99 < 18ms)
Dynamic Rate Card Engine evaluates pickup/dropoff H3 hexagons, real-time surge multiplier, and cold-chain compliance fee. Emits locked fee quote valid for 7 minutes.
T + 450 ms
3. Inventory Reservation & Escrow Pre-Authorization Redis Redlock → QPay NAPS
Stock is atomically reserved in merchant catalog. Payment Gateway pre-authorizes funds; initial ledger entry debits Customer Cash Clearing and credits Escrow Suspense Account.
T + 1.2 s
4. Transactional Outbox & Asynchronous Dispatch Matching Debezium CDC → Kafka order.created
Order is committed locally to PostgreSQL. Debezium streams CDC event into Kafka topic `order.created`. Dispatch Matcher pulls nearby active couriers from Redis GEO and solves Hungarian matching matrix.
T + 3.8 s
5. Courier Assignment & Push Handshake MQTT QoS-1 → Courier Edge App
Assignment offer is dispatched to courier mobile app with 45s accept window. Upon courier acceptance, state machine updates and merchant tablet triggers order kitchen/pack display.
T + 12 m
6. Merchant Pickup & Chain-of-Custody Lock BLE Datalogger → MoPH Tap
Courier arrives at merchant, scans item barcode, and activates cold-chain BLE temperature logger. Merchant escrow is formally locked in the double-entry sub-ledger.
T + 28 m
7. Geofence Dropoff, Verification & Instant Ledger Settlement Kafka order.settled → Escrow Ledger
Arrival geofence triggers customer OTP validation. Upon delivery completion, Kafka event `order.settled` executes atomic financial split: merchant payout, instant courier WPS mobile wallet credit, and platform net revenue.
